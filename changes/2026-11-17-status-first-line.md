# 2026-11-17 첫 줄 상태 표시([대기]/[완료]/[미완]/[답변]), 짧은 대기 응답, 완료일 때만 "완료 보고"

## 계기

10-13 규칙을 다섯 주 쓰고 나서 나온 불만이다.

- 완료 응답과 "진행할까요?" 로 승인을 기다리는 응답의 모양이 같아서, 끝난 건지 지시를 기다리는 건지 구분이 안 된다. 이미 끝났는데 "진행해" 라고 입력한 적도 있다.
- 진행할 거라 생각한 지점에서 한 번 더 묻는다. 글이 길게 풀어져 있어 눈에 안 들어온다.

## 측정

10-27 ~ 11-17 세션 로그, 자동 실행 프로젝트(Worklog, script, System32) 제외 1,769턴. 사용자 발화 분류는 정규식이고, 이어받은 세션의 중복 턴은 제거하지 않았다.

- 대기(2단계 재진술) 응답 154건은 길이 중앙 1,663자, 굵은 라벨 불릿 중앙 6개. 완료 응답 393건은 길이 중앙 1,584자, 굵은 라벨 불릿 중앙 6개. 모양이 사실상 같다.
- 대기 응답 154건 중 첫 100자 안에 아직 수정하지 않았음을 밝힌 것은 40건. 완료 응답의 상태 줄("완료 보고: 완료")은 메시지 앞에서 중앙 668자 뒤에 있었다.
- 제목은 "완료 보고" 인데 상태가 "확인 필요" 91건, "미완" 28건.
- "완료" 로 끝난 뒤 다음 발화가 "진행" 류 한마디였던 경우 15건. 이 중 11건은 하단 버튼 질문이 있어 그 질문에 대한 답일 수 있다.
- 2단계 재진술로 멈춘 147건 중 다음 발화가 단순 승인인 것이 73건(50%). 1단계 갈래 선택 58건은 단순 승인이 1건(2%)이라 실제 선택이 일어났다.
- 최종 메시지 길이 중앙 1,477자, 요청 길이 중앙 24자.

## 판단

설문으로 네 가지를 정했다.

- 모든 턴의 마지막 메시지 첫 줄에 상태 태그를 둔다. [대기], [완료], [미완], [답변]. 상태를 맨 위에서 읽게 하는 것이 목적이다.
- 대기 응답을 6줄에서 "할 일" 한 줄과, 해석이 갈릴 때만 쓰는 "확인" 한 줄로 줄였다. 적용 범위, 변경 파일, 변경 제외, 완료 기준 줄을 뺐고 1단계의 변경 제외 줄도 뺐다. 첫 줄이 대기임을 말하므로 끝의 "진행할까요?" 도 뺐다.
- "완료 보고" 제목은 끝났을 때만 쓴다. 제목의 "완료 | 미완 | 확인 필요" 를 없애고, 끝나지 않은 턴은 [미완] 과 막힌 것, 필요한 답, 여기까지 한 것 세 줄로 닫는다. "여기까지 한 것" 은 설문에 없었지만, 파일이 일부만 바뀐 상태를 알아야 되돌릴지 정할 수 있어 넣었다.
- 완료 뒤에 붙는 커밋·다음 단계 질문은 그대로 둔다.
- 감수한 것. 대기 응답에서 파일 목록이 빠져, 범위를 잘못 읽은 경우는 완료 보고의 "한 것" 에서야 보인다. 완료 기준과 "(배경 가능)/(전경 필요)" 꼬리표도 화면에서 사라지고, 확인 방법은 검증 줄에만 남는다.
- 리뷰어 입력은 바꾸지 않았다. 5줄 재진술을 리뷰어 프롬프트 안에서만 쓰게 해 `gate-reviewer.md` 는 그대로다.
- 넣지 않은 것. 파일 2개 이상이면 멈추는 기준, 질문에 대한 답변 길이, 완료 보고 6줄 축소, 항목별 이유 규칙은 답을 받지 못했거나 묻지 않아 그대로 뒀다.
