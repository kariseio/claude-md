# 2026-10-07 완료 보고 블록, 리뷰어 단계, 실행 가능한 완료 기준, 중단 규칙

## 계기

개발을 시킨 뒤 "제대로 됐나, 사이드 이펙트는 없나, 요구사항과 다른 데는 없나"를 세션 안에서 계속 검증시키고 있었다. 검증할 때마다 누락과 오류가 나오니 세션을 떠날 수가 없었고, 2~3개 세션을 동시에 띄우면 글이 읽히지 않았다.

실무자들의 워크플로우를 조사했다(Anthropic 가이드, Harper Reed, Willison, Hashimoto, Osmani, 컬리·subicura·동준상 등 국내 사례). 결론은 하나로 모였다. **세션에 붙잡히는 이유는 검증 수단이 없어서 사람이 검증 루프가 되기 때문**이다. 숙련자들은 작업을 띄우기 전에 pass/fail 검증을 글로 적고, 끝난 뒤에는 기계적 게이트와 새 컨텍스트의 리뷰어가 먼저 거르고, 사람은 증거만 본다. 같은 문제로 교정이 두 번 넘게 실패하면 세션을 버리고 새로 시작한다.

## 1차 초안과 그 검증

초안은 네 가지를 넣었다. 실행 가능한 완료 기준, 교정 2회 후 재시작, 리뷰어 단계(code-critic 또는 feature-dev:code-reviewer), 메시지 끝의 완료 보고 블록.

전역 반영 전에 두 방향으로 검증했다. 새 컨텍스트의 비평 에이전트가 변경분을 조사 보고서·Anthropic 현행 문서·훅 스크립트·에이전트 정의와 대조했고, 같은 작업을 옛 규칙과 새 규칙으로 헤드리스 실행해 비교했다(5회, 회당 약 1달러).

드러난 것.

- **훅이 마지막 메시지의 앞 200자만 보내고 있었다.** 블록을 맨 끝에 두라는 규칙은 카드에 아무것도 전달하지 못한다. 규칙에 적은 전제가 거짓이었다. 블로커.
- **리뷰어 조건 "게이트를 거친 변경"이 모호해서 실행에서 건너뛰었다.** 모델이 "단순 2파일이라 실행 안 함"이라고 스스로 면제했다.
- **지정한 리뷰어 둘이 규칙이 묘사한 리뷰어가 아니었다.** code-critic 은 opus + 세션 간 기억(새 컨텍스트 아님) + 전방위 비평이고, feature-dev:code-reviewer 는 Bash 가 없어 완료 기준 명령을 실행할 수 없다. 재리뷰 상한도 없었다.
- **"끝에 둬라" 규칙이 셋이었다.** 0번 "진행할까요?", 6번 "검증 못 한 주장 목록", 7번 블록. 편집을 끝냈는데 결정이 필요한 메시지에서 충돌했고, 초안을 보고한 메시지에서 실제로 충돌이 났다.
- **비코드 작업에서 가짜 명령을 유도했다.** "never prose" 를 지키려면 형식만 맞춘 검사가 나온다. 이 변경 자체가 반례였다.
- **중단 규칙의 주어가 불명했다.** Anthropic 원문은 "사용자가 두 번 넘게 교정"인데 초안은 Claude 가 세는 "correction rounds".
- **전역 CLAUDE.md 는 서브에이전트에도 로드된다.** 리뷰어가 블록을 쓰고 리뷰어를 또 띄울 수 있다.
- 옛 규칙으로도 "완료 기준" 줄은 이미 실행 명령으로 나왔고 pytest 원문도 붙였다. 새 규칙이 실제로 더한 것은 고정 블록과 "범위 밖 변경 / 남은 것" 명시였다. 비용은 같은 작업에서 약 1.7배(테스트 구성상 옛·새 규칙이 겹쳐 로드돼 과대).

## 판단

- 블록은 유지하되 **카드가 받을 수 있게 훅을 고쳤다.** `works_send_me.py` 가 "완료 보고" 이후를 보내고(최대 700자), 없으면 종전처럼 앞 200자. StopFailure 에도 오류 카드를 걸었다. CLAUDE.md 가 아니라 훅이 고쳐야 할 문제였다.
- 블록 줄 순서를 **상태 → 남은 것 → 범위 밖 변경 → 검증 → 한 것**으로 뒤집었다. 폰 카드는 앞 두 줄만 봐도 diff 를 열지 말지 정해야 한다. "출력 원문"은 "첫 오류 1줄"로. "범위 밖 변경"은 "없음 | 항목과 승인받은 턴"으로 바꿔 4번(사전 승인) 위반이 정상 결과처럼 보이지 않게 했다.
- 리뷰어 조건을 **"파일 2개 이상 또는 되돌리기 어려운 변경"**으로 변경의 모양에 묶었다. 두 번째 검사를 존재하지 않는 "엣지 케이스 목록"에서 **"완료 기준 명령이 실제 실행됐고 결과가 맞는가"**로 바꿨다. 재리뷰 상한 2회.
- 리뷰어는 **전용 에이전트 `gate-reviewer`** 로 만들었다(`agents/gate-reviewer.md`, sonnet, Read/Grep/Glob/Bash, 출력은 갭 목록 또는 "갭 없음"). 세 가지만 보고, 스타일은 보지 않고, 전역 CLAUDE.md 의 게이트·블록 규칙을 무시하라고 명시했다.
- "끝에 둬라" 충돌은 **"파일을 수정한 턴은 블록으로 끝낸다. 질문은 남은 것 줄에, '진행할까요?' 는 붙이지 않는다. 편집 없는 답변은 0번을 따른다. 서브에이전트는 블록 없이 보고만."** 으로 정리했다. 블록 첫 줄에 상태어를 넣어 카드 첫 줄로 판별되게 했다.
- 완료 기준은 **"실행하거나 눈으로 볼 수 있는 검사"** 로 넓혔다. 명령이 없으면 "수동 확인 — 볼 것". 형식만 맞춘 명령은 금지. 세션 종류를 Claude 가 정하는 문구는 빼고 "(배경 가능)/(전경 필요)" 표시만 남겼다.
- 중단 규칙의 주어를 **사용자**로 고정했다. "사용자가 같은 결함을 두 번 지적해도 남아 있으면". 사용자의 "계속"/"하라니까" 가 우선. Claude 자체 재시도는 3회에서 보고.
- 근거 설명 문장 3개와 "Never fill 검증 from memory"(6번·7번과 중복)를 지웠다.
- 넣지 않은 것. 블록 존재를 강제하는 prompt 형 Stop 훅은 2주 운용 뒤 지표를 보고 결정한다. Stage 2 게이트 형식은 건드리지 않았다.

## 2차 검증

수정본을 다시 비평 에이전트에 넘기고 헤드리스 3회를 더 돌렸다.

- 헤드리스: 두 파일 작업에서 gate-reviewer 가 실제로 떴고 "갭 없음"을 돌려줬다(비용 0.89달러, 옛 규칙 0.76달러). 게이트 정지 메시지의 완료 기준 줄에 "(배경 가능)" 이 붙었다. 비코드 두 파일 작업에서는 "수동 확인" 대신 파일 존재 검사 + 예시 실행 검사를 조합했다. 존재 검사는 약하지만 예시 실행은 실제 검증이라 남겨 둔다.
- 비평: 17건 중 13건 해결, 3건 부분, 1건 미측정(리뷰 1회 비용). HEAD 대비 순개선. 새로 잡은 것 둘은 훅 코드였다. `rfind("완료 보고")` 가 본문에서 블록을 언급한 문장에도 걸려 카드가 문장 중간부터 시작했고, Stop 훅 입력의 `last_assistant_message` 를 안 쓰고 transcript 만 읽어 지연 시 직전 턴 텍스트가 갈 수 있었다. 둘 다 고쳤다(줄 머리 앵커, last_assistant_message 우선).
- 같이 반영: 리뷰어 입력에 검증 줄 추가(2번 검사가 실제로 돌게), "남은 것"에 미검증 주장 포함(6번과의 충돌 해소), gate-reviewer frontmatter 에 `omitClaudeMd: true`(서브에이전트가 전역 게이트 규칙과 싸우지 않게. v2.1.271+).

## 느낀 점

- 규칙을 쓰기 전에 전제를 측정해야 했다. "훅이 마지막 메시지를 그대로 보낸다"는 코드 한 줄만 읽었으면 틀린 줄 알았을 문장이다.
- 조언형 규칙은 모델이 빈틈을 찾으면 빠져나간다. "게이트를 거친"처럼 해석이 갈리는 조건은 실행 한 번에 뚫렸다. 조건은 변경의 모양처럼 셀 수 있는 것에 묶어야 한다.
- 리뷰어는 "누구를 부르느냐"가 규칙 본문보다 세다. 서브에이전트의 자기 프롬프트가 부모 지시보다 강하게 작용하니, 세 가지만 보게 하려면 세 가지만 보는 에이전트를 만들어야 했다.
