# 2026-09-23 재진술 게이트 2단계 분리, 한글 라벨

## 계기

배포 다음 날, 다른 세션에서 나온 게이트 출력을 붙여넣었다. KMS credential 을 private 전용으로 정리하는 요청이었다.

```
Interpretation: KMS credential 을 private KMS 전용으로만 운영하고 공용 KMS 쪽 사용을 정리한다
Targets: needs confirmation (아래 해석에 따라 범위가 달라짐)
Will touch: 해석 확정 후 제시
Will not touch: Keycloak 토큰 2개(private sso-login·refresh 에 필수), 공용 KMS 노드 코드 삭제(별도 지시 없는 한)
Done when: 해석 확정 후 제시
Ambiguities:
  (A) credential 데이터만 정리 — ...
  (B) 키 이름 되돌리기 — ...
  (C) 공용 KMS 노드의 credential 사용 제거 — ...
  (D) credential subtype 정리 — ...
```

> 이런 식으로 응답이 나오는데 뭔가 이것도 가독성이 떨어지는 것 같아.

## 판단

- 게이트가 잘못 작동한 게 아니라, 형식이 맞지 않는 경우에 억지로 형식을 채운 결과였다. 6칸 중 3칸이 "확정 후 제시". 실제로 결정해야 할 것(A/B/C/D)이 빈칸 네 줄 뒤 맨 아래. 선택지 각각이 2~3절이고 추천이 없어서 네 가지 세계를 동시에 머리에 올려야 했다. "머리가 꼬인다"의 정확한 재현.
- 6칸 형식은 요청이 대체로 명확하고 모호한 부분이 한두 군데일 때용이다. 요청이 통째로 여러 갈래면 형식이 무너진다.
- 그래서 게이트를 두 단계로 나눴다. 해석을 얼버무림 없이 한 문장으로 못 쓰거나 읽는 방식에 따라 건드릴 파일이 달라지면 1단계: 선택지 2~4개, 각 한 줄(무엇이 바뀌는지 + 크기), 추천 하나에 이유 한 줄, 그리고 멈춤. 갈래가 정해진 뒤에 2단계 6칸. 채울 수 없는 줄은 생략하고 "확정 후 제시" 같은 자리채움은 금지. 왕복이 한 번 늘지만 각 왕복이 읽힌다.
- 라벨도 바꿨다. 영어 라벨과 한국어 내용이 여섯 줄마다 번갈아 나왔고, "건드림", "모호"는 명사가 아니라 라벨로 읽히지 않았다. 여섯 개를 전부 네 글자 명사구로 맞춰 콜론이 정렬되게 했다. 요청 해석 / 적용 범위 / 변경 파일 / 변경 제외 / 완료 기준 / 확인 필요. 가장 큰 개선은 "모호"에서 "확인 필요"로. 상태가 아니라 읽는 사람이 뭘 해야 하는지를 말한다.
- 두 글자 세트(요청 / 범위 / 변경 / 제외 / 완료 / 확인)도 검토했지만 "요청:"이 해석이 아니라 원문처럼 읽히고 "완료:", "확인:"이 흐려져서 뺐다.
- 규칙 본문은 영어 유지. 라벨은 사용자에게 보이는 출력이라 한글.

같은 요청을 새 형식으로 쓰면 이렇게 된다.

```
이 요청은 네 가지로 읽힙니다. 하나 골라주세요.

A. 저장된 공용 kms_access_token/kms_refresh_token 삭제. 코드 변경 없음.  ← 추천: "private 전용 운영"에 가장 가깝고 되돌리기 쉬움
B. private 클라이언트 3벌이 kms_* 키를 다시 읽게 통일. 지난 키 분리 커밋 일부 되감기.
C. 공용 KMS 노드 3개에서 credential 사용 제거. 노드 폐기까지 이어지는 큰 범위.
D. FE 생성 플로우의 subtype 을 private_kms 하나로. BE 는 LIKE 필터만.

변경 제외: Keycloak 토큰 2개 (private sso-login/refresh 에 필수)
```
